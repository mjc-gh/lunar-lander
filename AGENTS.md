# Repository Guide

## Commands

- Use Bun; `bun.lock` is the lockfile. Install with `bun install` and run locally with `bun run dev`.
- Full verification is `bun run test && bun run build`. There is no lint, format, or typecheck script.
- Run one test file with `bun run test src/game/simulation.test.js`; tests are colocated as `src/**/*.test.js`.
- `dist/` is generated by `bun run build` and must not be edited.

## Architecture

- `index.html` owns the UI markup; `src/main.js` wires DOM state, the animation loop, simulation, renderer, and player runtime.
- Keep game rules testable and browser-independent in `src/game/`. The simulation advances at the fixed `STEP_SECONDS` interval; do not substitute variable animation-frame time in physics updates.
- World coordinates are y-up. `src/render/canvas-renderer.js` alone converts them to Canvas's y-down coordinates.
- Terrain and the pad share vertices in `src/game/terrain.js`. Keep the pad segment flat and update collision queries and landing tests when changing its geometry.
- Player code crosses both `src/runtime/player-runtime.js` and `src/runtime/player-worker.js`. It must define synchronous `update(state)` and return `{ throttle, rotation }`; controls are clamped on the main thread. The disposable worker and 100 ms timeout prevent UI hangs but are not a security sandbox.
- `src/sample-program.js` is an intentionally incomplete editor default: it should crash until the player adds horizontal guidance. `src/sample-program.test.js` protects that complete-flight baseline when initial state, terrain, physics, telemetry, or landing limits change.
- When changing telemetry or the player API, update the worker/runtime boundary, `README.md`, and the API hints in `index.html` together.
